# Распознавание образов на Arduino Uno (без камеры)

Программы для **Arduino Uno** (ATmega328P: 8 бит, 16 МГц, **2 КБ SRAM**, 32 КБ flash).
Камера Uno не нужна ни в одном варианте — «образ» либо зашит в скетч, либо приходит
по Serial, либо снимается с аналогового входа A0.

Uno физически не тянет ни CNN, ни интерпретатор TFLite Micro (нужны сотни КБ RAM).
Поэтому «образ» ужат до минимума, а инференс написан прямым проходом на C:
крошечная int8-сеть `IN → HID → OUT`, веса лежат во flash (`PROGMEM`).

## Вариант 1 — цифра 8×8 (`digit_recognizer/`)

«Образ» = рукописная цифра 8×8 (датасет `sklearn digits`, значения 0..16).
Сеть **64 → 16 → 10**, int8, точность **0.969** (= как float32), веса ~1.3 КБ.

Откуда берётся картинка **без камеры**:
* 10 картинок зашиты в `test_images.h` (по одной на цифру) — прогоняются при старте;
* с ПК по Serial — ровно 64 байта (0..16): `uv run lr9-send-digit --port COM3`.

## Вариант 2 — форма сигнала на A0 (`signal_shape/`)

«Образ» = форма аналогового сигнала: 32 отсчёта с входа **A0**, нормированные в
0..16. Классы: `sine, square, triangle, sawtooth, flat, noise`.
Сеть **32 → 24 → 6**, int8, точность **≈0.87**, веса ~1 КБ.

Что подать на A0 (всё это НЕ камера):
* потенциометр — рукой рисуете ramp / triangle / flat;
* функциональный генератор или линейный выход звука через делитель;
* PWM-пин Uno через RC-фильтр — плата сама генерирует sine/square;
* ничего (плавающий вход) — обычно `noise` / 50 Гц наводка;
* с ПК по Serial — 32 байта: `uv run lr9-send-signal --port COM3 --shape triangle`.

## Ресурсы (обе программы влезают с запасом)

| | требуется | у Uno |
|---|---|---|
| веса int8 (flash/PROGMEM) | 1–1.3 КБ | 32 КБ |
| SRAM под инференс | < 200 Б | 2 КБ |
| время инференса @ 16 МГц | ~1–2 мс (печатает сама плата через `micros()`) | — |

## Сборка и прошивка

```bash
# 1. сгенерировать веса (в корне lr9):
uv run lr9-arduino-export     # -> digit_recognizer/model_data.h, test_images.h
uv run lr9-signal-export      # -> signal_shape/signal_model.h, signal_labels.h, test_signals.h
#    оба печатают ожидаемый вывод скетча (тем же int8-алгоритмом)

# 2а. Arduino IDE: открыть <вариант>/<вариант>.ino, плата "Arduino Uno",
#     Upload, Serial Monitor на 115200.

# 2б. arduino-cli:
arduino-cli compile -b arduino:avr:uno digit_recognizer
arduino-cli upload  -b arduino:avr:uno -p COM3 digit_recognizer
arduino-cli monitor -p COM3 -c baudrate=115200
```

## Проверка без платы

Host-инструменты в «сухом прогоне» (без `--port`) считают ответ тем же int8-кодом,
что зашит в скетч, и рисуют «образ» в ASCII:

```
$ uv run lr9-send-digit --sweep          # 10 цифр
$ uv run lr9-send-signal --sweep         # 6 форм
```

С `--port COM3` — реально шлют байты на плату и печатают её ответ.

## Как это соотносится с лекцией

| лекция (Pi / Jetson / Coral) | Arduino Uno |
|---|---|
| MobileNetV2, 224×224 RGB, ~3.5 млн параметров | MLP на **630–1210 параметров**, вход 8×8 или 32 отсчёта |
| TFLite / Edge TPU как рантайм | **рантайма нет** — прямой проход руками на C |
| INT8 ради размера/скорости | INT8 **обязателен**: float32 + эмуляция float на 8-битном AVR слишком тяжелы |
| FPS на кадрах с камеры | «инференсов/с» на цифрах / окнах сигнала; данные — из flash, Serial или A0 |

Главный вывод тот же, что в основной ЛР9: **чем меньше устройство, тем радикальнее
приходится ужимать и модель, и само представление образа** — от 224×224 RGB на Coral
до 8×8 grayscale (или 32 отсчётов сигнала) на Uno.
